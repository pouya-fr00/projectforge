# Generated Project Architecture

## Base layout

```text
my-app/
├── apps/
│   ├── web/
│   │   └── src/
│   │       ├── app/
│   │       ├── features/
│   │       ├── factory-generated/
│   │       └── extensions/
│   └── api/
│       └── src/
│           ├── app/
│           ├── features/
│           ├── factory-generated/
│           └── extensions/
├── packages/
│   ├── contracts/
│   ├── config/
│   ├── ui/
│   └── test-utils/
├── .project-factory/
├── docs/
└── tests/
```

## Generated vs editable

`factory-generated/` files contain a header:

```text
Generated by Project Factory. Do not edit directly.
Change .project-factory/project.json or extension points, then run project-factory sync.
```

`features/` contains source-owned module implementation users may customize. Checksums preserve provenance but do not block edits.

`extensions/` contains stable user hooks intended to survive sync.

## Independence

The generated application must not require Project Factory at runtime. The CLI may remain a dev dependency or be run through npx/pnpm dlx, but production code cannot call a Project Factory service.

## Generated repository guidance

Every generated project includes:

- `docs/ARCHITECTURE.md`;
- `docs/MODULES.md`;
- `.env.example`;
- exact verification commands;
- customization guide.
