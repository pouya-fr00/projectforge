# Dependency and License Policy

For every direct dependency record:

- purpose;
- official source;
- license;
- maintenance signal;
- runtime/build/dev classification;
- why existing code/platform is insufficient.

Reject:

- unclear or incompatible license;
- abandoned critical security dependency without mitigation;
- package that executes surprising install scripts;
- dependency added only for trivial formatting or utility logic;
- duplicate frameworks solving the same layer.

Audit copied UI/code assets and preserve required notices.
